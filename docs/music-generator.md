# MUSIC GENERATOR

楽器は独立した状態を持ち、16 分音符ごとのステップで動く。人間（または ARC = 環境条件）が決めるのは「密度」と「結合の強さ」の時間変化だけで、どの音をいつ鳴らすかは決めない（Conchordal の「Director は条件だけを形づくる」という考えを参考に独自実装）。

## 楽器の状態

| 状態 | 意味 |
|---|---|
| Energy | 発音できる力。毎ステップ減衰し、環境 (密度) と他の楽器からの働きかけで増え、発音で減る |
| Activity / awake | 目覚めているか。最初は「最も働きかけの強い楽器」だけが起きていて、他は相互作用を受けて目覚める（受けなければ一定時間後に環境が起こす。どちらもイベントとして記録） |
| Pitch | スケール上の度数。ランダムウォーク + 自分の音域の中心へ戻る力 |
| Rhythm | ユークリッドリズム `E(pulses, steps) + rotation` と速度倍率 |
| Resonance | 最近どれだけ共鳴したか |
| Timbre | −1…1 の音色のずれ（発音時の FM 深さ・フィルター・倍音の傾きに反映） |
| Memory | 最初の 4 音を主題として覚え、`memory_length` に応じて移調して再演する |
| Response sensitivity | DNA の `sensitivity` |

## 1 ステップの処理

1. 環境: エネルギー減衰、密度に応じた供給、音色と共鳴は 0 に戻ろうとする、総エネルギーの上限処理
2. 発音: 目覚めている楽器がパターンの拍でエネルギーが閾値以上なら発音（低密度ではパターンが間引かれる）
3. 伝播: 発音・共鳴・変化のイベントを他の楽器の反応ルールに渡す。成立確率 = 送り手の emission × イベント種別の重み × 受け手の sensitivity × ルールの強さ × ルール倍率 (UI) × 結合 (ARC) × 強さ
4. 反応: 予定された反応を決まった順に処理（不応期・1 ステップの上限つき）。反応が新しいイベントになり、さらに伝播する（深さ 3 まで）

双方向フィードバックの例（SONOVA-EXP-0002 で実際に起きたもの）:

```
tower が発音 → [同調] sunset がタイミングを合わせる → [リズム生成] tower のリズムが変わる → [リズム生成] bark のリズムが変わる
bark が発音 → [音色変化] sunset が明るくなる → [リズム生成] tower のリズム → [リズム生成] bark のリズム
```

## 記録

`experiments/phase2/<作品番号>.events.json` に全イベント（id・時刻・楽器・種類・音高・強さ・変化前後・**原因イベント id と効果**・深さ）と 4 ステップごとの状態スナップショットを保存する。`chains` は最も深い因果の連鎖を文章にしたもの。

## 展開 (ARC)

| ARC | 密度 | 結合 |
|---|---|---|
| BLOOM | 低い所から 62% 地点まで上がり、84% から余韻へ | 30% → 100%、終盤に弱まる |
| TIDE | 2 度の満ち引き | 中央で最大 |
| CASCADE | 前半は低く、45〜78% で上がる | 最初が最大、後半に弱まる |

最後の 3 秒は新しい音を出さず、共鳴とリバーブの余韻になる。構成名（emergence / interaction / bloom / ebb / afterglow）は ARC と実際の目覚めの時刻から導く。
